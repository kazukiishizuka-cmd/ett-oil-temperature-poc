# 変圧器 油温予測 PoC

ETT（Electricity Transformer Temperature）データセットを用いて、変圧器のオイル温度（OT）予測が
**運用・保全判断へ適用できる可能性があるか**を探索的に検証した記録。

報告スライド: [`slides/PoC_report.pdf`](slides/PoC_report.pdf)（23ページ）

---

## 結論

| | 内容 |
|---|---|
| **① 外部気象には大きな改善余地がある** | データ内の変数だけでは24時間先 **+0.5%**。対象時刻の気象8変数を完全に与える理想条件では24時間先 **+32.3%**・1週間先 **+36.1%**。実予報を使った性能ではなく外部気象情報の上限評価 |
| **② 正常値推定の候補を構成できた** | 油温履歴を使わず、負荷＋外部気象から油温を推定して **R² = 0.854**（ETTh2）。異常検知への利用可能性はあるが、異常ラベルによる検証は未実施 |
| **③ 外部気象を検証する根拠が得られた** | 候補地点の気温と油温には強い季節的共変動 **r = 0.977**（ETTh2）があり、外部気象追加時にも評価誤差が低下。因果効果・気温単独の寄与・実地点は未確定 |

補足として、探索に使った評価期間上では、分位点を変えることで**相対高温時間の再現率16%〜81%と誤報率の交換関係**が得られた。分位点は未見データで固定評価していない。
連続する相対高温時間を起点軸上でまとめると184区間中93区間を分類した。これは実際の設備イベント開始前の警報性能・通知回数を示す値ではない。

## セットアップ

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Python 3.9 / LightGBM 4.6 / PyTorch 2.8 で検証。深層モデルは Apple Silicon（MPS）または CUDA、無ければ CPU で動く。

## 再現手順

本検証の対象は **ETTh1 / ETTh2**（1時間粒度）。
ETTm1 / ETTm2（15分粒度）も同じコマンドで動く。予測ホライズン・ラグ・移動窓・周期・入力系列長・
外部気象の特徴量・高温閾値の窓・イベントのリードタイムはすべて時間または日数で指定し、
データ粒度に応じて行数へ換算しているため、`--datasets ETTm1` としても「24時間先」は24時間先、
「直近30日の95パーセンタイル」は30日を意味する。ただし掲載している結果は ETTh1 / ETTh2 のもの。

```bash
# 1. EDA（図7枚とデータ整合性チェック）
PYTHONPATH=src .venv/bin/python src/eda.py

# 2. 外部気象データの取得と代表地点候補の評価
#    data/external/ に取得済みのため、再取得が不要なら省略可
PYTHONPATH=src .venv/bin/python src/fetch_weather.py

# 3. ベースライン・線形・勾配ブースティング
PYTHONPATH=src .venv/bin/python src/run_experiment.py --datasets ETTh1 --tasks forecast nowcast
PYTHONPATH=src .venv/bin/python src/run_experiment.py --datasets ETTh1 --tasks forecast nowcast --external
PYTHONPATH=src .venv/bin/python src/run_experiment.py --datasets ETTh2 --tasks forecast nowcast --out metrics_ETTh2_base.csv
PYTHONPATH=src .venv/bin/python src/run_experiment.py --datasets ETTh2 --tasks forecast nowcast --external --out metrics_ETTh2_external.csv

# 4. 深層モデル（DLinear / PatchTST）
PYTHONPATH=src .venv/bin/python src/run_deep.py --dataset ETTh1

# 5. 分位点回帰（相対高温分類の探索）
PYTHONPATH=src .venv/bin/python src/run_quantile.py --dataset ETTh1

# 6. 気象予報の誤差に対する感度分析
PYTHONPATH=src .venv/bin/python src/run_sensitivity.py --dataset ETTh1

# 7. 集計と結果図の生成
PYTHONPATH=src .venv/bin/python src/analyze_results.py

# 8. 報告スライドのPDF化（要 Google Chrome）
bash slides/build_pdf.sh

# 粒度換算の回帰テスト（ETTm で24時間ラグが96行になることなどを確認）
PYTHONPATH=src .venv/bin/python src/test_granularity.py
```

## 検証の設計

課題文の但し書き「t=Tの油温を予測する際には、t=Tでの特徴量を使用して良い」を活かすため、
運用上の問いを2つに分けて検証した。

| | ナウキャスト（同時刻推定） | フォーキャスト（将来予測） |
|---|---|---|
| 問い | 油温計を見ずに、いま何℃のはずかを当てられるか | h時間後の油温を当てられるか |
| 入力 | 同時刻を含む負荷6変数と外部気象8変数。**油温の履歴は使わない** | 時刻tまでの全変数（油温履歴を含む） |
| 出力 | OT(t) | OT(t+h)、h = 1 / 24 / 168 |
| 用途 | センサ補完／異常検知に使う正常値推定の候補 | 予防保全へ向けた相対高温予測の探索 |

但し書きの許可は**ナウキャストでこそ本質的に効く**。同時刻の負荷を使えるからこそ
「今この瞬間の正常温度」を推定する候補となる。実測との乖離で異常を検出できるかは、異常ラベルで別途検証が必要。

## EDA で見つけた3点と、それぞれへの対処

| 発見 | 内容 | 対処 |
|---|---|---|
| **欠測・停止疑い区間** | 2016/12/5 09:00〜12/7 18:00 の58時間、負荷6変数がすべて厳密に0。欠測・計測異常・設備停止のいずれかは設備ログがなく確定不能 | 疑わしい区間として補間し、当該行を学習・評価から除外。補間方法の感度分析は未実施 |
| **レベルシフト** | ETTh1は2年で夏のピークが36℃→21℃に低下。原因は設備・計測・運用メタデータがなく未特定 | 短期変化量へタスクを限定して差分を予測。構造変化そのものを解決したわけではない |
| **記録分解能の差** | ETTh1は0.07℃刻み・ETTh2は0.0005℃刻み | 台間性能差へ影響した可能性がある候補要因。原因の確定には計測仕様が必要 |

さらに、**同時刻の負荷と油温の相関は最大 0.22、1階差分では相関がほぼ消える**（−0.07〜0.03）ことから、
「外気温と負荷が油温へ影響する」という物理仮説を置き、外部気象による探索検証に進んだ。OTと気温の差を負荷効果へ分解したものではない。

## 主要な結果

### 将来予測（ETTh1・MAE ℃・4分割検証の平均）

| モデル | 1時間先 | 24時間先 | 1週間先 | 1週間先の改善 |
|---|---|---|---|---|
| Persistence | 0.552 | 1.933 | 2.970 | 基準 |
| SeasonalNaive | 0.742 | 2.967 | 5.085 | −71.2% |
| Ridge | 0.621 | 3.059 | 5.297 | −78.4% |
| PatchTST | 0.550 | 1.974 | 2.763 | +7.0% |
| DLinear | 0.544 | 1.868 | 2.761 | +7.0% |
| LightGBM | 0.526 | 1.924 | 2.621 | +11.8% |
| **LightGBM ＋外気温** | **0.506** | **1.308** | **1.898** | **+36.1%** |

深層モデルはこのデータ規模（有効データ約17,000点）で優位に立たなかった。
PatchTST は LightGBM の **42倍の学習時間**（71.6秒 vs 1.7秒）で精度は下回る。外部気象込みの LightGBM（13.7秒）と比べても 5倍。

### 将来予測（ETTh2・MAE ℃・4分割検証の平均）

| モデル | 1時間先 | 24時間先 | 1週間先 |
|---|---|---|---|
| Persistence | 0.929 | 3.292 | 5.467 |
| SeasonalNaive | 0.731 | 4.927 | 9.210 |
| Ridge | 0.638 | 7.552 | 9.874 |
| LightGBM | 0.416 | 3.283 | 4.866 |
| **LightGBM ＋外気温** | **0.386** | **2.090** | **2.892** |

**同じ手法でも2台で結論が変わる。** 1時間先のPersistence比はETTh1が+8.4%、ETTh2が+58.4%で7倍違う。
記録分解能・計測系・設備運用の違いが影響した可能性があるが原因は未特定。導入前に設備と計測の仕様確認が必要。

### ナウキャスト（油温の履歴を一切使わない推定）

| 入力 | ETTh1 MAE | ETTh1 R² | ETTh2 MAE | ETTh2 R² |
|---|---|---|---|---|
| 平均を答えるだけ | 6.76 | −5.05 | 10.18 | −1.51 |
| 負荷6変数のみ | 6.01 | −3.38 | 6.43 | −0.02 |
| **負荷＋外部気象** | **5.10** | **−1.66** | **2.11** | **0.854** |

ETTh2では負荷＋外部気象から観測OTの**分散の85%を再構成**でき、異常検知に使う正常値推定の候補となった。
異常ラベル・残差閾値・誤報率は未検証。ETTh1で精度が低い原因も特定できていない。

### 相対高温時間の予測（分位点回帰・ETTh1・1週間先）

機器仕様が不明なため「予測時点から見た直近30日の95パーセンタイル超過」を探索用の相対高温と定義した。設備の危険温度を表すものではない。

| 設定 | MAE | 再現率 | 誤報率 |
|---|---|---|---|
| Persistence | 2.970 | 0.160 | 6.2% |
| 分位点 0.5 | 1.873 | 0.497 | 4.6% |
| 分位点 0.7 | 2.019 | 0.573 | 6.8% |
| 分位点 0.8 | 2.199 | 0.657 | 9.3% |
| **分位点 0.9** | 2.711 | **0.808** | 16.5% |

分位点0.5でもMAEはPersistenceを下回る（1.873対2.970）。同じ評価期間上で分位点を比較した探索値であり、設計確定後の未見性能ではない。PoCの成果は最良の1モデルではなく、相対高温の再現率と誤報率の交換関係である。

### 相対高温区間の分類（起点軸・ETTh1）

上表の再現率は**時刻単位**で、「高温だった時間の何割に警報を出せたか」を測っている。
連続する相対高温時間を1区間として起点軸上で集計した。実設備の異常イベントや、イベント開始前の運用警報を評価したものではない。

| 予測先 | モデル | 検知 | 検知率 | リードタイム | 警報/週 |
|---|---|---|---|---|---|
| 24時間先 | **LightGBM＋外気温** | 89 / 174 | **0.51** | 24h | **2.24** |
| 24時間先 | Persistence | 82 / 174 | 0.47 | 23.5h | 2.76 |
| 24時間先 | SeasonalNaive | 113 / 174 | 0.65 | 24h | 6.13 |
| 1週間先 | **LightGBM＋外気温** | 93 / 184 | **0.51** | 168h | **1.93** |
| 1週間先 | Persistence | 60 / 184 | 0.33 | 168h | 2.78 |
| 1週間先 | SeasonalNaive | 97 / 184 | 0.53 | 168h | 5.38 |

表の「警報/週」は起点軸上の予測超過区間数。「リードタイム」は予測起点から対象時刻までの猶予であり、実イベント開始前の初回警報時間ではない。

**評価の定義**：高温イベントは「直近30日の95パーセンタイルを超える時間帯」で、連続する時間帯を1件と数える。
検知は「イベント区間内で一度でも警報が出たこと」。リードタイムは警報を出した予測起点から対象時刻までの猶予で、
イベント開始と同時に鳴れば予測ホライズンと同じ値になる。
評価は予測起点の軸で行っているため、対象時刻の軸でイベント開始より前に出た警報は数えていない。
見逃し1件と空振り点検1件のコスト比が分かれば分位点は一意に決まるが、その比を持っているのは保全部門であってモデル側ではない。

### 気象予報の誤差に対する感度（ETTh1）

上の改善幅は対象時刻の気象を完全に知る oracle 条件で測っている。
実運用で入るのは予報なので、気温予報に標準偏差 1〜3℃ の正規ノイズを与えて改善幅の残り方を見た。

| 予報誤差 | 24時間先 | 1週間先 |
|---|---|---|
| ±0℃（oracle） | +31.8% | +35.5% |
| **±1℃** | **+30.1%** | **+35.4%** |
| **±2℃** | **+27.5%** | **+32.0%** |
| ±3℃ | +25.1% | +30.5% |

実際の気温予報の誤差は24時間先で1〜2℃、1週間先で2〜3℃程度とされるため、**現実的な条件でも +25〜32% は残る**見込み。
±0℃を100とした残存率では、±1℃で95〜100%、±2℃で87〜90%、±3℃で79〜86%。

なお ±0℃ の値（+31.8% / +35.5%）が本編の表（+32.3% / +36.1%）とわずかに異なるのは、LightGBM の bagging・feature sampling による実行差。
誤差の影響は同一実行内での比較として読む。

ただしこの模擬には限界がある。与えたのは時刻ごとに独立な正規ノイズで、実際の予報誤差は系統的で自己相関を持つため楽観側に振れる可能性がある。
ノイズを与えたのは気温のみで、残る7変数と休日特徴は完全既知のまま。過去の実予報データによる検証は未実施。

## 置いた仮定

課題文の「不明点は合理的な仮定を置き、その仮定を明記した上で進めてください」に従い、以下を仮定した。

| 仮定 | 根拠 |
|---|---|
| 2016/12/5 09:00〜12/7 18:00 の負荷ゼロは**欠測・計測異常・停止の疑いがある区間** | 負荷6変数が同時に厳密な0。設備ログがなく真因は確定できないため疑わしい区間として除外 |
| ETTh1 と ETTm1 は**同一変圧器**の異なる粒度である | 毎正時の値を突き合わせ、全17,420点・全7変数で差が厳密に0であることを確認 |
| 南京の気象系列を**代表プロキシ**として使う | 16候補中で学習期間の整合度が僅差の最上位。実地点を同定したものではなく、ETTh1とETTh2が同一地点とも限らない |
| 油温の単位は**℃**である | データセットに記載はないが、値域と季節変動の振幅が℃として自然。絶対的な危険水準の設定には使えない |
| 予測ホライズンは **1 / 24 / 168 時間** | 「監視」「翌日の運用計画」「週次の点検計画」を想定して置いた探索用設定。利用者要件による妥当性確認は未実施 |
| 探索用の相対高温は**直近30日の95パーセンタイル超過** | 機器仕様がないため置いた比較用定義。設備リスクや絶対的な危険温度を表さない |
| 将来予測では対象時刻 **t+h の気象8変数が完全に既知** | 実予報ではなく再解析の未来値を使うoracle条件。実運用性能ではなく外部気象情報の上限評価 |

## 限界

1. **未来の気象8変数を完全に使用** — 実予報ではなく再解析の未来値を使うoracle条件。誤差を模擬した感度分析では±1〜3℃でも+25〜32%残ったが、独立な正規ノイズによる模擬であり実予報データでの検証は未実施。気温単独の寄与も未分離
2. **地点は未特定** — 南京0.919と武漢0.918がほぼ同点。南京は代表プロキシであり実地点の同定ではない
3. **単位と機器仕様が不明** — 定格・冷却方式・容量が分からず、絶対的な危険水準を設定できない
4. **2台のみの検証** — 台によって結論が割れるため、母数2台では一般化できない
5. **ETTh1 のレベルシフトの原因が未特定** — 設備台帳との突き合わせが必要
6. **異常検知を検証していない** — 評価したのは正常値推定の精度。異常ラベル・残差閾値・誤報率・検知遅延は未評価
7. **設計確定後の独立した評価をしていない** — 報告値は全期間を4分割した検証の平均で、モデル比較のための交差検証値。差分ターゲット・外部気象・地点・分位点を選んだ後も同じ期間で報告しているため、設計を固めた後の未見データに対する性能ではない。探索的PoCの推定値として読む必要がある
8. **外部データのモデルを固定していない** — Open-Meteoのモデル指定なしで取得したBest Match。再取得で値が変わる可能性がある
9. **相対高温は設備リスクではない** — 30日95パーセンタイルは比較用定義。絶対危険温度・継続時間・温度上昇率は未反映
10. **イベント指標は起点軸の分類** — 実イベント開始前の警報時間と運用通知件数は未評価

## 今後の改善方針

1. **最優先: 外部気象の現実条件での再評価** — 使用モデルを固定し、気温単独・実予報誤差・候補地点の感度を検証
2. **次点: 計測系の素性確認** — 記録分解能・サンプリング周期・欠測処理の仕様、機器の改修履歴。モデル構築より前に確認すべき
3. **用途を2つに絞った第2フェーズ** — ①正常値推定からの異常検知 ②相対高温から実リスク警報への置換。異常ラベルと設備仕様で成立性を検証
4. **現時点では保留: 深層モデルへの追加投資** — 本PoCの検証範囲では優位性を確認できず。多数の変圧器を横断学習できる規模になった段階で再評価
